GitResolve (`@clyrisai/gitresolve`) is an npm library and CLI tool that takes raw candidate inputs — portfolio websites, resume PDFs, direct GitHub/GitLab/Bitbucket profile links, or individual repository URLs — and resolves them into clean, structured git profiles with confidence scoring and categorized repository data. Whether you're building a hiring pipeline, a talent sourcing tool, or an ATS integration, GitResolve removes the manual work of extracting and normalizing the git presence from a candidate submission.

## The Problem It Solves

Hiring teams collect candidate data from many sources: job application forms with a plain-text "GitHub URL" field, resume PDFs that bury hyperlinks in annotations, portfolio sites built with JavaScript-heavy frameworks, and shared spreadsheets full of unvalidated links. The result is a messy mix of dead links, partial usernames, repo URLs mistaken for profile URLs, and external contributions tangled up with personal projects.

GitResolve classifies each input, scrapes it with the right browser strategy, parses PDF text and annotation layers, disambiguates who the actual candidate is, and returns a single `ResolverResult` object with clear fields for the owner profile, owned repositories, contribution signals, and any warnings encountered along the way.

## Key Capabilities

- **Portfolio scraping** — fetches and parses candidate portfolio sites, extracting all git links from HTML content
- **Resume PDF parsing** — extracts both raw text and deeply buried hyperlink annotations from PDF files, including remote URLs
- **GitHub, GitLab, and Bitbucket support** — fully resolves profiles, repos, pull requests, and issues across all three providers
- **Owner disambiguation** — separates the candidate's own repositories from external repos they have referenced or contributed to
- **Confidence scoring** — each result includes a `high | medium | low | none` confidence rating for the resolved owner profile
- **CLI and programmatic API** — run interactively from the terminal or import directly into any Node.js or Bun backend

## Supported Input Types

GitResolve automatically classifies each input before processing it. You can also pass a `--type` hint via the CLI to override classification.

| Input Type | Example | What Happens |
|---|---|---|
| `portfolio` | `https://janedoe.dev` | Page is fetched and scraped for all git links |
| `git_profile` | `https://github.com/janedoe` | Profile page is scraped; repos and username extracted |
| `repo_url` | `https://github.com/janedoe/my-project` | Repo page is scraped; owner is resolved |
| `resume_file` | `./resume.pdf` | PDF text and hyperlink annotations are parsed |
| `resume_url` | `https://example.com/resume.pdf` | PDF is fetched, then parsed as above |
| `linkedin` | `https://linkedin.com/in/janedoe` | Flagged and skipped — not scrapeable |
| `unknown` | Unrecognized string | Returned with a warning; no processing attempted |

## Browser Providers

GitResolve supports three browser providers for fetching page content. The `createProvider()` function automatically selects the best available one using the resolution order: **puppeteer → browserless → fetch**. You can override this with the `--provider` CLI flag or the `BROWSER_PROVIDER` environment variable.

| Provider | Requires | JavaScript Rendering | Best For |
|---|---|---|---|
| `puppeteer` | Bundled dependency (auto-installed) | ✅ Full | SPAs and JavaScript-heavy portfolio sites |
| `browserless` | Running Docker container | ✅ Full | Server environments, CI/CD pipelines |
| `fetch` | Nothing | ❌ None | Static HTML sites, fast fallback |
