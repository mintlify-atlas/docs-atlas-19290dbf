`BrowserlessProvider` delivers the same full JavaScript rendering as `PuppeteerProvider` — rendered SPAs, dynamic content, client-side routing — but offloads all browser execution to a separate [Browserless](https://www.browserless.io) Docker container. Because the headless Chromium binary lives in the container rather than your application, you get complete JS rendering without adding a heavy native dependency to your deployment image. This makes `BrowserlessProvider` the preferred choice for production API servers, container-based CI/CD pipelines, and any environment where a local Puppeteer binary is impractical or prohibited.

## When to Use

- **Production servers** — keep your application image lean by running Chromium in a dedicated sidecar container
- **CI/CD pipelines** — spin up the Browserless container as a service alongside your test or build job
- **Restricted environments** — platforms that block native binary execution but allow outbound HTTP calls to a local service
- **Teams sharing infrastructure** — run a single Browserless instance that multiple GitResolve workers connect to concurrently

## Docker Setup

Start the Browserless container before running GitResolve:

```bash
docker run -d --name browserless -p 3000:3000 ghcr.io/browserless/chromium
```

<Info>
  The container exposes port `3000` by default. Change the host port mapping (e.g., `-p 8080:3000`) and update `BROWSERLESS_URL` accordingly if port `3000` is already in use on your host.
</Info>

## Usage

### Direct instantiation

```typescript
import { BrowserlessProvider } from '@clyrisai/gitresolve';

// Pass the base URL explicitly
const provider = new BrowserlessProvider('http://localhost:3000');

// Or rely on the BROWSERLESS_URL environment variable
const provider = new BrowserlessProvider();

const result = await scrapePortfolio('https://janedoe.dev', provider);
await provider.cleanup(); // no-op — stateless REST, nothing to release
```

### Via factory

```typescript
import { createProvider } from '@clyrisai/gitresolve';

const provider = await createProvider('browserless');
```

### Via CLI

```bash
gitresolve --provider browserless --browserless-url http://localhost:3000 https://janedoe.dev
```

<Tip>
  Set the `BROWSERLESS_URL` environment variable to avoid passing `--browserless-url` on every CLI invocation:

  ```bash
  export BROWSERLESS_URL=http://browserless:3000
  gitresolve --provider browserless https://janedoe.dev
  ```

  This is especially useful in Docker Compose setups where the container is reachable by service name rather than `localhost`.
</Tip>

## Configuration

| Source | Value | Description |
|---|---|---|
| Constructor argument | `new BrowserlessProvider('http://...')` | Highest priority — overrides everything else |
| `BROWSERLESS_URL` env var | `export BROWSERLESS_URL=http://...` | Used when no constructor argument is provided |
| Default | `http://localhost:3000` | Fallback when neither of the above is set |

## How It Works

<Steps>
  <Step title="POST to /content">
    For each `getPageContent` call, `BrowserlessProvider` sends a `POST` request to `{baseUrl}/content` with a JSON body containing the target URL and `gotoOptions` (timeout and `waitUntil`). The Browserless container launches a Chromium tab, navigates to the URL, waits for the condition, and returns the fully rendered HTML as the response body.
  </Step>
  <Step title="Availability check">
    `isAvailable()` sends a `GET` request to `{baseUrl}/json/version` with a 3000 ms timeout. If the container responds with a 2xx status, the provider is considered available. This check is used by `createProvider()` during auto-detection.
  </Step>
  <Step title="Cleanup">
    `cleanup()` is a no-op. Because every request is a self-contained HTTP call and the provider holds no local state, there is nothing to release on the GitResolve side.
  </Step>
</Steps>

## Options

Pass a `BrowserProviderOptions` object as the second argument to `getPageContent` to override defaults:

| Option | Type | Default | Description |
|---|---|---|---|
| `timeout` | `number` | `30000` | Navigation timeout in milliseconds, forwarded to Chromium inside the container as `gotoOptions.timeout`. |
| `waitUntil` | `'load' \| 'domcontentloaded' \| 'networkidle0' \| 'networkidle2'` | `'networkidle2'` | When to consider navigation complete, forwarded as `gotoOptions.waitUntil`. |

```typescript
const html = await provider.getPageContent('https://janedoe.dev', {
  timeout: 60000,
  waitUntil: 'networkidle0',
});
```

<Note>
  `cleanup()` is a no-op for `BrowserlessProvider`. The provider is stateless — it holds no open connections or browser handles between requests. You may still call `cleanup()` for consistency when writing code that works with multiple provider types interchangeably.
</Note>
